3) HOW MOCKUPS GET LINKED (brief)
--------------------------------------------------------------------------------

Source docs:
  - uploads/mockups/README_UPLOAD_INSTRUCTIONS.txt
  - uploads/mockups/UPLOAD_TEMPLATE.txt
  - uploads/mockups/3901Y/README.txt (and mirror under static/)
  - import_mockup_images.py: NOT in working tree (removed historically; only
    __pycache__/import_mockup_images.cpython-314.pyc remains)
  - Live linking code: utils/mockups.py + routes/admin.py

Workflow (from README + current code):

1. Place images under uploads/mockups/{STYLE}/ (e.g. 3901Y/).
   Expected naming in docs: {STYLE}_ColorName_front.jpg / _back.jpg
   (Actual 3901Y files use Bella+Canvas descriptive names:
    BELLA_+_CANVAS_3901Y_{Color}_Front_High.jpg / _Back_High.jpg)

2. Optionally sync/copy to static/uploads/mockups/ so Flask can serve them
   (app.py syncs uploads/mockups -> static/uploads/mockups).

3. Runtime resolution (utils/mockups.py):
   - Searches static/uploads/mockups and uploads/mockups (and static/images/products)
   - Matches by style folder + color + view (front/back)
   - Used for shop carousel / design preview even when DB URLs are missing

4. Admin linking (POST /admin/products/link-mockups):
   - create_products_from_mockup_folders(): creates Product + ProductColorVariant
     for any mockup folder that has no product yet
   - ensure_variant_mockup_urls(): fills missing front/back image URLs on variants
     from the mockup folder, and creates variants for colors found on disk but
     not yet in DB

5. S&S sync path (admin sync-api) can also sync only styles that have mockup
   folders (sync_mockup_styles), then variants get mockup URLs ensured.

Bottom line: files in uploads/mockups/{style}/ are the source of truth for
colors/images; admin "link mockups" (or ensure_variant_mockup_urls) writes those
paths onto ProductColorVariant; the shop also falls back to scanning the folder
directly. import_mockup_images.py is documented but no longer present as .py.
